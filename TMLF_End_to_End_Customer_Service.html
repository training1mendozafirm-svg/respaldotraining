⚡   Tipos de Escalación — Tipificación en Sheet / Chat
🤔
Duda
El asesor no sabe cómo responder al cliente o no tiene acceso a la información necesaria. Requiere asistencia del Team Leader.
  • Cliente con caso muy inusual fuera del flujo normal
  • Asesor necesita verificar algo en Dropbox (sin acceso)
  • Notificación rara en USCIS que el asesor no identifica
  • Esposo del cliente falleció y no sabe qué estatus asignar
🔄
Escalación
El cliente requiere acción de otra área que no es Customer Service. Se canaliza a través de Slack o formulario.
  • Permiso de trabajo sin actualización → Backoffice
  • Cliente solicita sus recibos iniciales → Backoffice
  • Documentos enviados / paquete de bienvenida → Follow-up
  • Solicitud de biométricos o huellas → Backoffice
🚨
Emergencia
Cinco situaciones que requieren reporte inmediato al Team Leader y acción urgente. El asesor solo contiene al cliente.
  • 📁 File Request — pide su expediente
  • ⚖️ Bar Complaint — amenaza con queja a la barra
  • 👩‍⚖️ Pide hablar directamente con MGM
  • 🔴 Amenaza de demanda legal
  • ⭐ Bar Review — amenaza con reviews negativos
📲
Requiere Callback
El cliente necesita o solicita una llamada de abogado. Siempre requiere autorización del Team Leader antes de ofrecerse.
  • Cliente insistente que exige hablar con abogado
  • Caso con Rejection o Decision que el cliente no conoce
  • Asesor detecta que el caso requiere asesoría legal urgente
  • Dictaminación: revisar con TL antes de escalar
📣
Aviso
Comunicados informativos que no requieren escalación a ningún área. El TL queda informado; CS resuelve en llamada.
  • Cliente pregunta por noticias de Trump / cambios migratorios
  • Cliente recibió cita de biométricos antes que la firma
  • Consultas sobre demandas a abogados (noticias externas)
✅
Pide Autorización
Áreas específicas cuyo formulario de escalación requiere aprobación explícita de Team Leader antes de enviarse.
  • Cancelaciones — autorización TL obligatoria
  • Escalaciones a Backoffice — autorización TL obligatoria
  • Reagendar citas de biométricos (I-90)
💬   Canales Slack — Acceso Asesores
💰
Collections
Todo lo relacionado con finanzas y pagos del cliente. CS toma pagos directos, pero escala a este canal cuando el cliente necesita información de balance, plan de pagos o reembolsos.
  • Cliente solicita su balance completo de pagos
  • Acuerdos o plan de pagos personalizado
  • Seguimiento a reembolso pendiente
📋
Follow-Up
Escalaciones por documentos, seguimiento de trámites y paquetes. Anteriormente también recolección de documentos (hoy lo lleva DMX).
  • Cliente enviando / recibiendo documentos
  • Paquete de bienvenida no recibido
  • Cita de biométricos USCIS (huellas)
🚫   Información Restringida — NO se comunica al cliente
❌
Rejections
No se informa. Se escala a Callbacks para que un abogado notifique. Si el cliente ya sabe y pide el documento → File Request.
❌
Decisions
No se informa. Mismo protocolo que Rejection. El abogado es quien debe comunicar cualquier decisión formal de USCIS.
❌
RFE / NOID
No se informa directamente. Si el cliente lo pide, se trata como File Request. Se escala el reporte.
❌
NTA (Notice to Appear)
No se informa en ningún caso. Se escala con el área de Removals. Si piden el documento → File Request.
❌
Dictaminación
No se dice "está en dictaminación". Se parafrasea: "se encuentra bajo revisión para definir la mejor estrategia".
⚠️
NOIDs (en TramCase)
No se comparten al cliente. Se escala como File Request para obtener autorización antes de enviar.
📝   Plantilla de Notas — TramCase
Tipo
Incoming Call (llamada de entrada)  |  Outgoing Call – Chat Request (saliente de ClickUp)
Reason
Motivo por el que se contacta el cliente. Ej: "Incoming call – request payment" / "Case status – permiso de trabajo"
Solution
Resumen de lo que se le dijo al cliente y qué acción se tomó. Ej: "Se tomó pago, se envió recibo, se escaló balance a Collections"
Internal Note
Acciones internas que el cliente NO debe conocer. Ej: "Escalar a backoffice – recibos no enviados"
Behavior
Estado emocional del cliente en la llamada. Ej: "Calmado", "Molesto", "Muy alterado", "Confundido"
Client Number
Número de cliente confirmado. Si no lo tiene: fecha de nacimiento, dirección o email registrado. Anotar si confirmó o no confirmó.
Ejemplo:
Incoming call – request payment + recibos iniciales. El cliente realizó un pago mensual de $350. Se tomó el pago y se generó recibo (adjunto). Solicitó recibos iniciales de la semana anterior, no recibidos. Se escaló a grupo Collections para envío de balance. Behavior: calmado. Client number: Confirmed.
👥
Team Leader — Supervisión Activa en Todo Momento
El TL monitorea llamadas en tiempo real vía Dashboard RT. Si una llamada supera 10 minutos, interviene. Autoriza callbacks, resuelve dudas complejas, toma llamadas de emergencia y transfiere a su extensión cuando el cliente exige un supervisor.
⏱ Máx. 10 min / llamada
